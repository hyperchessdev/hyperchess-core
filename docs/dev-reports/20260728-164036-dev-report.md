## Decisions of record

- **Do not delete or recreate the GitHub repository.** Reversed from the original plan once it
  became clear `main` already has a strong, CI-verified, merged foundation (PR #1). Confirmed
  explicitly with the user. Future sessions should not revisit repo deletion without a similarly
  explicit, freshly-informed re-confirmation.
- **Licensing is `GPL-3.0-or-later` uniformly** across every crate and every npm package
  (`@hyperchess/core`, `board`, `store`, `theme`, `wasm`) — per PR #1's decision. This session's
  earlier MIT/GPL split narrative (built on stale package.json state) is superseded and should
  not be reintroduced.
- **`docs/hyperchess-laws.md` and `docs/search-architecture.md` (lowercase, PR #1's naming) are
  the canonical files** for rules and search internals respectively. Do not recreate an
  uppercase `docs/HYPERCHESS-LAWS.md` or a competing search-internals doc — this session
  deliberately built `docs/ARCHITECTURE.md`/`docs/FAQ.md`/etc. as complements, not replacements.
- **File-header `Version:` is independent of crate/package SemVer** — see
  `docs/FILE-HEADER-CONVENTION.md`. All 148 files start at `1.0.0` regardless of prior file age.
- **"HyperChess Developer Team"** is the copyright/maintainer identity used in file headers,
  `CITATION.cff`, `GOVERNANCE.md`, and `MAINTAINERS.md`, per explicit user instruction — existing
  content that already said "HyperChess Contributors" (only `CITATION.cff`) was updated; content
  with a real, specific contact (`hyperchessapp@gmail.com` in `CODE_OF_CONDUCT.md`/`SECURITY.md`)
  was left untouched.
- A live-looking GitLab personal access token was found embedded in the repo's `gitlab` git
  remote URL (`git remote -v` / `.git/config`) at session start. **Not touched or removed** —
  flagged to the user for their own rotation/cleanup, since it's credential material outside
  this session's scope.
