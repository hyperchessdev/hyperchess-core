## What was done

### 1. Engine inspection (vs `docs/hyperchess-laws.md`)
The engine implements the full law set: 12×12 board, Eagle/Hawk jumpers (movegen, SEE values,
unblockable-check handling), rank-3/10 pawn double-step + en passant, rank-12/1 promotion incl.
E/H, g-file castling, 224-half-move rule, raptor insufficient material. The search stack was
already unified: every public searcher name delegates to the canonical `TimedSearcher`
(pinned by the `searcher_unification_golden` test).

### 2. Search hardening (new strength, HyperChess-unique)
- **Countermove refutation table** (144×144, butterfly-indexed by the opponent's previous move)
  in `TimedSearcher`, ordered in a strict band between killers (7 500) and quiet history (≤ 6 900).
- **Raptor bonus** (+400 in the quiet band): quiet Eagle/Hawk moves landing within Chebyshev ≤ 4
  of the enemy king are tried early — raptor checks cannot be blocked by interposition.
- 5 new ordering unit tests pin the score bands; all golden/regression suites unchanged.

### 3. Pre-existing breakages found and fixed
All from the earlier profile-rename commit (`9e330c0`):
- `hyperchess-wasm` **did not compile for wasm32** (stale `ProSearcher` import + duplicated
  `"strategic"` match arm) — the WASM SDK was unbuildable on main.
- `hyperchess-driver` failed `clippy -D warnings` (`eq_op` duplicated comparison + duplicated
  match literal).
- `cargo fmt`/`cargo metadata` failed from git worktrees (excluded CUDA crate lacked a
  `[workspace]` table).

### 4. Zero-dependency engine
`hyperchess-eval` + `hyperchess-rules` + `hyperchess-search` now build with **zero external
crates** (`cargo tree`: `search → rules → eval`):
- `bitflags` deleted (declared, never invoked); `lazy_static` → `std::sync::LazyLock`;
  `rand` → dev-dependency in rules (test-only) and removed from search (RandomBot + MCTS
  shuffle now use the engine's own XorShift64* PRNG, Zobrist-seeded → **MCTS is exactly
  reproducible**); optional `getrandom` dropped. Optional `wasm` feature adds only `js-sys`.
